# 首版产品与交互设计

项目名称：**NEO NEU**。

本文定义产品范围。具体页面内容、位置与交互布局以 [UI 页面布局设计](06-UI页面布局设计.md) 为准；下方早期首页草图只作概念说明。

## 已确定的需求

产品面向学生，以本科生为首个验证角色；主要自用，适配主流 Android。组件库指定 Miuix。首版覆盖常用查询功能，后续再考虑业务办理。没有必要自建账号系统、管理后台或集中保存师生数据的服务器。

首版的价值是把分散在门户和教务系统中的信息整理成稳定、易读、能离线查看的手机页面。

## 原生体验要求

今日、课表、成绩、考试、余额、消息、待办及设置全部使用 Compose + Miuix 原生组件。业务数据由适配器查询、解析和缓存，不将远程 HTML 作为主要界面，也不以隐藏 WebView 常驻刷新所有查询数据。富文本消息转换为受控的原生展示内容。

学校官方网页仅用于必要的认证流程；用户主动打开官方原文时使用独立浏览器。认证过程中允许必要网页，不意味着查询功能采用网页实现。尚未打通的接口显示明确的未完成或暂不可用状态，不用网页替代原生页面作为交付。

本地缓存优先呈现；网络和解析工作不阻塞 UI 线程；切换导航保留页面状态，课表切周优先读取已有数据。滑动与刷新在真机 release 构建上检查，不能仅凭“原生”就认定流畅。

## 功能范围

| 功能 | 首版内容 | 明确边界 |
| --- | --- | --- |
| 课表 | 本学期及历史学期、周切换、今日课、课程详情、校区与作息时间 | 不执行学校的课表确认；不改学校排课 |
| 成绩 | 学期筛选、课程、学分、原始成绩、官方绩点、详情 | 不提交成绩复查；不擅自套用绩点公式 |
| 考试 | 已安排与未安排、时间、地点、座位、说明 | 不报名、签到或接受考试承诺书 |
| 校园卡 | 余额、数据时间；卡状态在来源确认后显示 | 不充值、不挂失、不生成支付码 |
| 网费 | 余额及来源时间 | 流量、在线设备等另需网关接口，不由余额接口推断 |
| 消息 | 来源、时间、内容、官方已读状态、筛选和分页 | 默认不向学校发送标记已读请求 |
| 待办 | 待办、已办、申请状态列表 | 只读摘要，不执行办理或审批 |
| 服务 | 常用查询入口、搜索、本地收藏 | 收藏先只存在本机，不写门户收藏接口 |
| 设置 | 深浅色、首页卡片顺序、缓存、登录状态 | 不修改学校账号资料或密码 |

教务系统内的消息与门户统一消息是两个来源，分别标识，不把一方计数当作全校消息总数。校园资讯作为低优先级可选卡片，不影响主要查询任务。

## 导航与首页

四个底部入口：今日、课表、查询、我的。成绩和考试放在查询页首行，并可固定到首页。消息在今日右上角进入。

```text
今日                           消息
当前学期 · 第 N 教学周

下一节课
课程名称 · 开始时间
校区 · 教学楼 · 教室       查看详情

成绩    考试    校园卡    网费

今天的课程                全部
课程 A  起止时间  地点
课程 B  起止时间  地点

校园卡余额       网费余额
默认可隐藏       每项显示更新时间

待办摘要                  查看列表

今日       课表       查询       我的
```

教学周取学校校历，日期默认学校时区 Asia/Shanghai。不同卡片独立刷新，余额失败不阻塞课表。首次登录只加载首屏所需信息，成绩详情、历史学期等按需请求。

## 课表交互

周视图默认显示本周，提供回到本周与学期选择；大字体或窄屏可切为每日列表。课程详情使用底部抽屉，显示课程、教师、校区、教室、周次、节次、来源和更新时间。

实际教务页面已确认存在以下情况，必须支持：同一课程不同周次更换教室、实验课、尚未安排节次的课程、百分制与等级制考核。数据不能压缩为“课程名 + 星期 + 时间”一条记录。

按日期和来源记录标识保存课程实例。同一名称的连续两节课可在展示层合并，但只有教师、地点、日期、来源和衔接时间一致时才合并，底层保留原始分节。未安排节次的课程放到独立列表，不能静默丢弃。

学校返回多个校区时查询并汇总，不能照搬当前网页“默认取第一个校区”的行为。跨校区时间冲突要明确显示；作息时间按学期和校区读取。

## 成绩与考试

成绩页优先显示学校给出的原始成绩、课程绩点和总平均学分绩点。已经发现学校提供总平均学分绩点接口，所以无需先自行计算。总平均值与某学期筛选结果分开标注，避免误称“本学期绩点”。

实际成绩页包括课程名、课程号、学分、总成绩、绩点、重修重考、获得学年学期、课程类别、课程性质、通识选修课类别、考试类型、替代课程和成绩认定信息。首屏展示核心字段，余项置于详情。新系统已能展示该账号迁移前的历史成绩，但不能推断所有历史记录都完整迁移。

考试显示已安排和未安排两部分。查询时观察到本学期无已安排考试，这是空状态样本，不是有考试样本验证。考试字段可由服务端 `showkeys` 控制，客户端不把缺字段解释为无权限之外的其他结论。

如果学校要求先确认承诺书或完成其他业务才能继续查看，提示去官方页面处理，不自动完成这类确认。

## 消息与待办

消息列表支持全部、未读、已读；“本机看过”和“学校已读”分别存储。阅读已经获得的消息内容不自动向服务端标记已读。打开原系统可能触发原系统的已读或访问记录，应在“查看原文”旁说明。

待办保留来源系统、标题、时间与业务状态。无待办和加载失败必须区分。第一版不复制网页中的申请、审批和全部标记已读按钮。

## 状态与隐私

| 情况 | 显示与动作 |
| --- | --- |
| 首次未登录 | 学校官方登录入口与功能说明，不展示仿真个人数据 |
| 离线且有缓存 | 展示最后成功数据和时间，允许本地浏览 |
| 登录失效 | 保留页面位置，一次登录提示，成功后恢复读取 |
| 单项失败 | 卡片级错误与重试，不把失败渲染为 0 元或无课程 |
| 空结果 | 标明学期、时间范围与来源，必要时提供官方查询入口 |
| 数据格式变化 | 保留旧缓存，提示更新失败，记录脱敏诊断信息 |

余额默认可隐藏，应用切换预览可隐藏成绩和余额。课程名称、成绩等不写入崩溃日志。退出时清理会话和关联个人缓存；如保留离线数据，必须由用户明确选择。

## 视觉实现

使用 Miuix 原生主题、卡片、导航、搜索框、下拉刷新、底部抽屉和设置项。颜色使用主题语义值，提供跟随系统、浅色、深色；首版以普通不透明表面为默认，不依赖模糊特效。课表网格是业务组件，需要使用 Compose Layout 自行实现。

主流适配重点是 API 29 及以上、常见国产系统、不同 WebView 版本、手势导航、深色模式和大字体；构建最低版本暂定 API 24，最终由真实设备测试决定支持承诺。
