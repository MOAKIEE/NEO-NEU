# 学生校园查询 App 设计与接口研究

更新日期：2026 年 9 月 22 日。

开发顺序：**后端数据接入 AI 先完成工程骨架、认证、查询、缓存和共享契约，交接后前端 AI 再实现原生页面**。具体职责和启动提示词见第 05 份文档，不并行开工。

当前决定：Android 原生 Kotlin + Compose + Miuix，面向学生，优先满足本科生自用；第一版主要查询课表、成绩、考试、校园卡与网费余额、消息和待办，不实现充值、选课、挂失或申请提交。

**界面硬性要求：全部核心查询页面使用 Compose + Miuix 原生渲染，不做 WebView 套壳，不把学校网页嵌入主页面。** 数据通过查询适配器取得并转换为本地模型。网页只可用于必要的官方认证，以及用户主动选择的“在浏览器查看原文”；官方认证结束即返回原生页面。接口未打通的功能应标为未完成，不得用嵌入网页冒充已实现。

## 研究进度

已完成 APK 静态解析、Miuix 源码与 Maven 制品检查、现有浏览器登录态下的门户／新教务／一卡通／缴费大厅／消息中心页面检查，以及这些页面使用的公开 JavaScript 研究。没有输入或收集学校密码，没有执行付款、选课、挂失、课表确认或申请提交。

研究结果已超出“找到 URL”的阶段：个人课表、成绩详情、考试查询等已有请求代码证据。但尚未完成独立 Android 客户端的登录与接口回放，也未取得所有接口的实际 JSON 响应。当前浏览器工具能查看页面与资源地址，不能直接导出完整网络请求；一次直接打开日历 JSON 地址被客户端拦截。因此下面的文档明确区分页面实测、网络资源观察、源码契约与仍待验证的内容。

个人姓名、学号、具体成绩、余额、Cookie 和票据不写入交付文档。必要的原始脚本与核验材料位于项目 `research/`，用途见 [研究材料说明](../research/README.md)。过时初稿及临时研究文件已删除。

当前需求和实现方向以本索引列出的五份文档为准。`research/` 仅用于追溯证据，不是待实现功能清单，也不是可直接运行的 App 源码。
