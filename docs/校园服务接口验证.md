# 校园服务接口验证记录

验证日期：2026-09-25。本文仅维护真实登录取得的历史协议证据及其边界。校园服务扩展代码已回滚；当前实现与验收状态分别见[开发指南](开发指南.md)和[验证状态](验证状态.md)。

## 验证环境与边界

- Android 模拟器 `TestDevice`，Android 16 / API 36，user 系统。
- 官方 APK：`com.sunyt.testdemo`，3.1.8 / 2026090001，与项目根目录 `base.apk` 的已记录版本一致。
- 用户先在官方 App 中打开 e 码通。该 App 未暴露可连接的 WebView DevTools socket，因此**没有直接抓取官方 APK 的内部请求**，也没有修改、重签名、注入或绕过其 TLS 校验。
- 随后在本项目独立 `verification` 调试宿主中临时添加 `ServiceVerificationActivity`，打开学校同源官方页面。用户分别自行完成学校认证和学生邮箱登录；认证不由代理代填，不读取密码表单。该临时 Activity 已撤销，正式 App 没有包含此调试宿主。
- 通过调试 WebView 在设备内执行已由官方脚本确认的读取请求，仅返回类型、协议状态和布尔比对结果。未将二维码、邮件正文、主题、发件人、账号、Cookie、sid、完整 URL 查询串、HAR 或个人截图导出到项目或文档。
- WebView 的正常登录会话仍由设备上的学校网页/WebView 管理；没有把官方 App 的 Cookie 或票据复制到验证宿主。
- 本轮证据来自一个学生账号、一台模拟器及当前网络；不外推为所有账号、真机、校内外网络均已验收。

## e 码通

### 入口与认证

- 官方页面：`https://ecode.neu.edu.cn/ecode/`，官方 APK 的公开入口另含 `#/`。
- 官方认证入口：`https://ecode.neu.edu.cn/ecode/api/sso/login`。匿名访问实际返回 HTTP 302，跳转主机为 `pass.neu.edu.cn`。
- 匿名 `GET /ecode/api/qr-code` 返回 HTTP 401；用户在验证宿主自行认证后，同源取码返回 HTTP 200。
- 当前只证明 e 码通域的官方网页登录及取码可用。门户或教务已连接不能代替 e 码通自身探针。

### 取码响应：修正静态调研中的歧义

读取请求为 `GET https://ecode.neu.edu.cn/ecode/api/qr-code`，不带业务查询参数。以下是实际响应的类型结构，未列出任何码值或个人值：

```text
root.data: array
  item.type: null
  item.attributes:
    qrCode: string
    createTime: string（13 位十进制数字）
    qrInvalidTime: string（13 位十进制数字）
```

三个字段处于 **attributes 同级**。不是 `qrCode.createTime` 或 `qrCode.qrInvalidTime`，也不是需要序列化的二维码对象。本轮码字符串为可打印 ASCII，长度 27；这只是样本事实，不应据此把所有账号/未来码格式限定为固定长度。

连续三次读取（间隔约 10 秒）均成功，后两次码字符串均发生变化。仅在设备内比较字符串，未输出其内容或摘要哈希。三次均满足：

```text
Number(attributes.qrInvalidTime) - Number(attributes.createTime) = 11000
```

时间戳量级及其与 HTTP `Date` 的差值支持“Unix 毫秒时间戳”解释；三次 `createTime - HTTP Date` 分别处于 278–531 毫秒范围，符合 HTTP Date 秒精度。本轮请求往返约 118–127 毫秒。不要把这些网络时延固定成学校业务规则。

这里验证的是服务端**声明的**有效期，未通过实际闸机证明失效边界、刷新后旧码是否立即作废，或不同码种的接受规则。

### 二维码编码与刷新

- 官方应用脚本把 `attributes.qrCode` 赋给 `options.text`。
- 官方 vendor 脚本的 `qr` 指令将 `options.text` 直接传给二维码库的 `addData`，默认纠错等级为 H，类型/版本自动选择。未发现需要为载荷附加 URI、JSON 包装或账户前缀的转换。
- 未复制官方二维码库源码；将来原生绘制必须编码原字符串，不能调用对象的 `toString()` 或生成自定义码。
- 官方页面初始化 `qrInvalidTime = 10000`，据此创建 `setInterval`。资源时间线可见约 10 秒一次的请求；额外人工只读探测会插入其他时间点，不能把相邻所有请求间隔都解释成自动刷新周期。
- 官方取码回调却读取 `attributes.qrCode.qrInvalidTime - attributes.qrCode.createTime - 2000`。真实载荷为字符串，运行中的页面该计算结果是 `NaN`；既有 interval 不因赋值自动重建，所以仍以最初约 10 秒周期执行。

原生实现应以已核验的同级时间戳计算有效时间，采用单调时钟管理展示期限，并保守扣除网络耗时与时钟/HTTP Date 精度余量；这些是客户端设计建议，尚不是已实现行为。刷新要使用可取消任务，处理后台、恢复、退出、换号、并发请求与旧请求晚返回。取码失败或有效期不可信时不得保留可扫码图案；动态码不得进入 Room、日志、剪贴板、SavedState 或截图材料。

### 未核验与禁止调用

- 未核验 `user-priority` 的权限语义，不把二维码可获取等同于具备通行权限；不要自行推导学校规则或支付能力。
- 未核验刷新撤销、实际扫码、设备时钟偏差、账号切换、登录失效、限流及断网恢复。
- 未调用 `/ecode/api/register`。它即使使用 GET 也具有登记副作用，必须排除在只读白名单之外。
- 未读取身份、照片作为本轮实现必需字段。

## 学生邮件（Coremail）

### 认证与会话证据

官方入口为 `https://mails.neu.edu.cn/`。本次在 Android WebView 中登录后进入 `/coremail/hxphone/`；不要改用教工 `mail.neu.edu.cn`，也不要把通用 IMAP 帮助中的示例服务器当作学生邮箱服务器。

官方页面的 Angular `User.getCurrentUser().sid` 在登录后持有当前会话 sid，`simpleCall` 会将它加入业务请求查询参数。这次只在页面内使用它，不返回到终端、不写入文件。没有验证通用 OAuth 或门户 Cookie 到邮箱的交换协议。

对相同的只读 `mbox:getAllFolders` 请求，使用正确的协议头后得到：

| 认证条件 | HTTP | 业务码 |
| --- | --- | --- |
| 当前邮箱 sid + 同源 Cookie | 200 | `S_OK` |
| 当前邮箱 sid，不携带 Cookie | 202 | `FA_SECURITY` |
| 同源 Cookie，不带 sid | 202 | `FA_UNAUTHORIZED` |

因此，本轮条件下**两者都需要**。不能把 sid 当成可单独使用的 bearer token，不能把 HTTP 2xx 当成业务成功，也不能把门户登录状态作为邮箱连接状态。仅核验了“缺失凭据”的分支，未证明所有过期会话都会返回相同错误码。

后续实现仍需可信 origin 校验、内存 sid 交接与退出策略。不能从本段协议证据推断正式 App 已通过新账号验收；不得持久化 sid、读取密码表单或记录含 sid 的 URL。

### 请求传输格式

本轮下列读取均通过：

```text
POST https://mails.neu.edu.cn/coremail/s/
query: func=<已核验的只读函数>, sid=<当前邮箱会话，仅内存>
Accept: text/x-json
Content-Type: text/x-json
X-CM-SERVICE: PHONE
body: JSON 对象
```

路径、POST、JSON 请求体和请求头先由官方脚本/运行中请求确认，再使用同源 `fetch` 独立复核文件夹和分页，排除只依赖页面服务封装的误判。

**响应格式陷阱：**最初独立请求只设置 Content-Type、未指定 Accept，HTTP 200 的成功结果实际是 `application/xml;charset=UTF-8`，根元素为 `result`，包含 `code` 及有类型的 array/object/scalar 节点。这不是学校返回坏 JSON。补齐上述官方请求头后，响应为 `text/x-json;charset=UTF-8`，可按 JSON 解析。正式适配仍应检查 Content-Type、业务码和结构，不能无条件解析/执行返回文本。

### 已核验的只读函数与参数

| func | 本轮请求体 | 结果与用途 |
| --- | --- | --- |
| `mbox:getAllFolders` | `stats: true, mboxa: ""` | `S_OK`；系统收件箱的 id 为 1，本轮同时核对其系统标志及“收件箱”名称后才查询 |
| `mbox:listMessages` | `fids: [收件箱 id], mode: "count", order: "receivedDate", desc: true, start: 0 或 20, limit: 20, summaryWindowSize: 20, skipLockedFolders: true, topFirst: true, returnTotal: true, mboxa: ""` | 两页均 `S_OK`；第二页非空，两页 ID 不重叠，总数一致 |
| `mbox:listMessages` 未读筛选 | 在上方参数中增加 `filterFlags: {read: false}` | 成功返回未读样本，供只读性比对 |
| `mbox:getMessageInfos` | `ids: [来自列表的 id], mboxa: "", summaryWindowSize: 1` | `S_OK`；核对同一记录的服务器标志 |
| `mbox:readMessage` | 见下方显式参数 | `S_OK`；读取正文后未改变样本的服务器未读状态 |

正文读取沿用已核对的官方请求字段，显式覆盖 `markRead`：

```text
id: 来自收件箱记录的 id
mboxa: ""
part: ""
mode: "html"
filterHeads: true
filterStylesheets: false
filterLinks: false
filterImages: false
autoName: true
markRead: false
returnAntispamInfo: true
stripContentTrs: false
returnHeaders: {Sender: "A"}
supportTNEF: true
```

`mode: "html"` 是官方请求参数，不代表本轮返回了 HTML 样本。此请求只取得数据，没有把正文插入页面或加载其中的资源；`filterImages: false` 也不意味着原生实现可以自动加载外链图片。上述非核心参数是否可精简尚未逐项验证。

### 只读性验证步骤及结果

1. 以服务器 `filterFlags.read = false` 查询收件箱，选择其中一封邮件，只在设备内保留它的 id。
2. 用 `mbox:getMessageInfos` 读取该记录的服务器 flags。
3. 只调用 `mbox:readMessage`，显式 `markRead: false`，不经过官方 UI 的“打开邮件”流程。
4. 再次读取同一记录 flags，并再次请求学校端未读列表。
5. 所有调用均 `S_OK`；前后 flags 比较相同；该 id 仍在学校端未读结果中。

官方前端包装方法默认按账户权限计算 `markRead`，普通官方 UI 也可能主动要求设为已读。因此原生实现必须在网络层强制 `markRead: false`，不能只靠 UI 不显示“标已读”按钮。

未调用 `mbox:updateMessageInfos`、发送、删除、移动、星标、读回执或附件下载接口。只读性结论覆盖当前样本与参数组合，不代表官方网页的普通阅读操作也只读。

```text

  var: array<object>
```

日期字符串匹配 `YYYY-MM-DD` 开头，具体时区语义尚未核验。服务器 flags 是稀疏对象，本轮列表未显式提供 `read: false`，不能使用“必须出现布尔 false”的筛选方式，否则会漏掉真实未读邮件。本轮以服务器未读过滤及复查证明该样本的未读状态；更一般的缺失字段解释仍需参考协议和更多样本。

### 尚未覆盖

- 独立原生会话生命周期：登录完成识别、sid 安全交接、冷启动重认证、会话过期、账号切换、退出及清除缓存。
- HTML 正文、复杂 MIME、附件、内嵌图片、外链追踪图片、读回执邮件与恶意内容样本。
- 空收件箱、末页、邮件同步变动引起的翻页漂移、超大列表、错误/限流及部分成功 `S_PARTIAL_OK`。
- IMAP 学生服务器和授权方式没有验证，也没有使用 IMAP。本轮 Web 接口已经提供原生只读的可行路径，不需要据通用 IMAP 示例猜测服务器。
