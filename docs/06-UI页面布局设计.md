# UI 页面布局设计

设计日期：2026-09-23。用于后端交付后的前端设计与实现。本文件只规定页面内容、位置和交互，不包含 UI 代码，不表示相关接口已完成。

沿用 01 的功能范围与 05 的后端先行顺序；**页面布局以本文为准**。后端实际可用字段少于设计时采用本文的缺省状态，不伪造数据，不为填满卡片扩展采集范围。

## 1 整体结构

风格采用 Miuix 的大标题、圆角分组、清晰列表和轻量弹层。全局保持留白，主要信息直接可读。第一版不放开屏广告、校园新闻轮播、AI 悬浮球、运营横幅或装饰性统计图。

### 四个主页面

| 底部导航 | 主要回答的问题 | 内容 |
| --- | --- | --- |
| 今日 | 今天要去哪上课，有什么需要查看 | 下一节课、今日课程、快捷查询、余额摘要、考试与待办摘要 |
| 课表 | 这周和这个学期怎么安排 | 周课表、每日列表、课程详情、未安排课程 |
| 查询 | 我要查某项信息 | 成绩、考试、校园卡、网费、消息、待办、日程、服务目录 |
| 我的 | 账号和应用如何设置 | 学生身份、连接状态、显示偏好、数据与隐私、关于 |

底部导航固定，四项同时显示图标和文字。主页面切换保留滚动位置、筛选与当前周。详情页不显示底部导航，使用左上角返回，回到原入口及原位置。

### 页面关系

```text
今日 ─ 下一节课／今日课程 → 课程详情抽屉
     ├ 成绩／考试快捷入口 → 对应查询页
     ├ 余额卡片 → 校园卡／网费详情
     └ 右上消息 → 消息中心 → 消息详情

课表 ─ 课程格子 → 课程详情抽屉
     ├ 学期／周次选择 → 选择抽屉
     └ 未安排课程 → 课程列表 → 详情

查询 ─ 成绩 → 成绩详情
     ├ 考试 → 考试详情
     ├ 校园卡／网费 → 各自详情
     ├ 消息／待办／日程 → 各自列表与详情
     └ 学校服务 → 服务说明 → 用户主动打开官方网页

我的 ─ 账号与连接／外观／首页设置／数据与隐私／关于
```

## 2 通用位置和样式

| 元素 | 设计规则 |
| --- | --- |
| 页面边距 | 手机左右 16dp；卡片内部约 16dp |
| 间距 | 同卡片元素约 8dp，卡片之间 12dp，区块之间 20—24dp |
| 标题 | 主页面用大标题；详情页使用紧凑标题栏 |
| 正文 | 默认约 16sp，辅助信息约 13—14sp，跟随系统字体大小 |
| 卡片 | 遵循 Miuix 默认圆角体系；全页统一，不每张卡一个样式 |
| 颜色 | 中性背景、清晰文字、一个主题强调色；支持系统／浅色／深色 |
| 按钮 | 一屏最多一个突出主操作；查询页面以刷新、筛选为主 |
| 点击范围 | 建议不小于 48dp；整行可点时提供右侧箭头 |
| 状态 | 加载用局部占位，失败用局部提示，正常状态不持续显示绿色横幅 |
| 安全区 | 底部列表和按钮不得被导航栏、手势条或键盘遮挡 |

状态色辅助表达含义，同时必须有文字。成绩高低不铺满红绿，余额不设置未经确认的“低余额”阈值。金额隐藏用统一眼睛按钮，不使用点击金额才能发现的隐蔽操作。

“更新于 09:40”通常放区块标题右侧或卡片底部，用较弱文字；只有离线或更新失败时才提高提示强度。不同来源的更新时间分别显示，不能把首页最后刷新时间套给所有卡片。

## 3 今日首页

### 从上到下的固定顺序

1. **标题区**：左侧“今日”，右侧消息图标；标题下显示日期、星期、教学周。
2. **必要状态条**：仅在登录失效、离线等影响本页时出现；正常时不占位。
3. **下一节课卡片**：本页视觉重点。
4. **快捷查询一行**：成绩、考试、待办、全部查询，四个等宽入口。
5. **今天的课程**：按时间排列的简短列表。
6. **校园生活**：校园卡和网费两张并列摘要卡。
7. **最近考试、待办摘要**：有可信数据时显示；无事项时不放两个大空卡片。
8. 底部固定导航。

首次进入主屏，目标是看到日期、完整下一节课卡片、快捷查询及今日课程开头。不能为此压缩大字体用户的文字；小屏允许自然向下滚动。

```text

9 月 23 日 周三 · 第 N 教学周

┌ 下一节课 ────────────────────────┐
│ 10:00—11:40                     │
│ 课程名称                        │
│ 南湖校区 · 教学楼 · 教室         │
│ 第 3—4 节              查看详情 ›│
└─────────────────────────────────┘

   成绩       考试       待办       全部

今天的课程                       看课表 ›
08:00   课程 A                   已结束
10:00   课程 B                   待上课
14:00   课程 C                   待上课

校园生活                            隐藏
┌ 校园卡 ────────┐ ┌ 网费 ─────────┐
│ ¥ ••••        │ │ ¥ ••••        │
│ 更新于 09:40  │ │ 更新于 09:40  │
└───────────────┘ └───────────────┘

最近考试／待办摘要（有内容时展示）

 今日         课表         查询         我的
```

示意文字和时间均为虚构，不是用户实际记录。

### 下一节课的状态

| 情况 | 卡片内容 |
| --- | --- |
| 当前有课 | 标签改为“正在上课”，展示该课起止时间、地点 |
| 今天还有课 | 显示下一次课程的时间、名称和地点 |
| 今日课程结束 | “今天的课程已结束”，若后续数据已缓存，可附“明天第一节” |
| 今天没有课 | “今天没有已安排课程”，提供“查看本周”；不据此判断没有未安排课程 |
| 数据尚未加载／查询失败 | 保持卡片位置，显示加载或重试；不显示“今天没课” |
| 时间冲突 | 主卡标注“同时有 2 项安排”，点击打开列表供选择，不静默选择一门 |

老师、完整周次、课程号不塞进首页主卡，放详情。第一版不做地图路线和上课打卡按钮。卡片时间明确即可，不依赖持续跳动的秒级倒计时。

### 列表和摘要

今日课程按开始时间排序，每行左侧时间、中间名称与地点、右侧简短状态；默认最多显示四项，超过时显示“查看全部 N 项”。主卡与列表允许出现同一课程：前者用于立即查看，后者保留整天顺序。

余额默认隐藏，两张卡可分别进入详情；右上眼睛控制本页余额展示。大字体时两张卡改为上下排列。待办摘要显示总量与最多两条标题，不放“立即办理”。考试摘要显示最近一场的日期、课程和地点，不重复整份考试列表。

首页区块的隐藏与排序在“我的 → 首页设置”调整。首版固定保留标题、状态区、下一节课和底部导航；其余区块允许隐藏，避免拖动布局增加误触。

## 4 课表页

### 顶部和网格

第一行：左侧“课表”，右侧“列表视图”切换和更多菜单。第二行：学期选择。第三行：上一周、当前周与日期范围、下一周；偏离本周时出现“回本周”。第四行是校区筛选，默认“全部校区”。

网格顶部固定星期和日期，左侧固定节次与起止时间，当前日期用强调色。网格纵向滚动，长按不是必需操作。避免整个页面左右滑动切底部标签，以免与课表手势冲突。

```text
课表                         列表   ⋯
2026—2027 秋季学期                  ▾
‹        第 N 周 · 9/21—9/27        ›
全部校区 ▾                    回本周

       一    二    三    四    五   …
       21    22    23    24    25
1—2   ┌──────┐        ┌──────┐
08:00 │课程名│        │课程名│
09:40 │教室  │        │教室  │
      └──────┘        └──────┘
3—4         ┌──────┐
10:00       │课程名│
11:40       │教室  │
            └──────┘

未安排节次的课程  N 项              ›
```

### 窄屏与周末

普通手机默认优先保证每列可读：每列最小宽度建议约 60dp，七天可以横向滚动，左侧节次栏固定；标题区提示当前可见日期，右缘保留后续列的视觉线索。日期列默认从周一开始，但所有七天都可访问，周末有课不能隐藏。

课表横向拖动只移动日期列；换周使用明确的上一周／下一周按钮与周选择抽屉，避免同一手势既换周又滚列。宽屏可完整显示七天。大字体建议每日列表，并记住用户选择，不强行缩小字体。

### 课程格子

优先放课程名和教室；课程名最多显示约两行，完整信息在详情。用较浅背景区分课程，文字有足够对比度。实验课显示短标签“实验”，不依赖不同颜色判断类型。

同时间冲突：两项且宽度允许时并排；更多或空间不足时显示“2 项课程”集合卡，点击选择。禁止相互覆盖到无法点击。跨校区课程保留校区缩写，详情展开全称。

“未安排节次的课程”入口位于网格下方，同时出现在更多菜单，确保网格较长时仍可找到。存在此类课程时显示数量，不计入“今日无课”的已安排数量。

### 课程详情抽屉

从底部展开，标题为课程名，右上关闭。按以下顺序展示：

1. 当前选中日期、周次、起止时间和节次。
2. 校区、教学楼、教室。
3. 教师、课程号、课程类型。
4. “其他上课安排”列表：相同课程的其他周次或地点。
5. 来源、更新时间、数据过期说明。

内容较多时抽屉可扩展并滚动。地点仅支持查看和复制，不放未实现的导航按钮。不显示“修改课程”“签到”“确认课表”。

## 5 查询主页

标题“查询”，下方固定一个搜索入口，提示“搜索查询功能”。这里只搜索功能名称及别名，不混入消息正文、个人成绩或校园全文检索。

页面按两列卡片分组：

```text
查询
[ 搜索查询功能                    ]

学习
┌ 成绩查询 ──────┐ ┌ 考试安排 ──────┐
│ 成绩与官方绩点 │ │ 时间与考场     │
└────────────────┘ └────────────────┘
┌ 课表与校历 ────┐ ┌ 我的日程 ──────┐
└────────────────┘ └────────────────┘

校园生活
┌ 校园卡余额 ────┐ ┌ 网费余额 ──────┐
└────────────────┘ └────────────────┘

消息与事务
┌ 消息中心 ──────┐ ┌ 待办与申请 ────┐
└────────────────┘ └────────────────┘

学校服务                         查看目录 ›
```

“课表与校历”先回到课表页，通过更多菜单进入校历、作息表，避免重做一套课表页面。尚未接入功能显示“暂未接入”短标签，点击说明当前限制；不能出现会打开网页但看起来像原生查询的卡片。

搜索结果是单列，名称、用途、状态和箭头。无匹配时显示“未找到相关查询”，给清除关键词动作。大字体时所有卡片改为单列。

学校服务目录是次级入口。列表项带“官方网页”标签，先进入简单服务说明，再由用户点击“在浏览器打开”；核心查询页面不会通过此路径替代。

## 6 成绩页

### 内容位置

1. 紧凑标题栏：返回、成绩。
2. 独立统计卡：“官方总平均学分绩点”，大数字，下方明确“全学程／学校统计口径”，刷新时间在卡片底部；若统计范围尚不明确则写“学校返回统计值”，不称为本学期。
3. 学期选择行：当前学期或全部学期；同一行右侧为排序按钮。
4. 课程名搜索框，搜索当前已加载范围。
5. 成绩课程列表，列表标题注明所选范围与条数。

```text
‹ 成绩

官方总平均学分绩点
     —.—
统计范围说明 · 更新于 HH:mm

全部学期 ▾                       排序
[ 搜索课程名称                     ]

课程名称                         88
3 学分 · 必修 · 绩点 3.8          ›
获得学期                         初修
──────────────────────────────────
课程名称                         合格
1 学分 · 考查 · 绩点以学校结果为准 ›
```

数字均为排版示例。成绩右对齐，百分制和“优／良／合格”等文字保持相同视觉等级，不转换为虚构分数。初修、重修等以小标签显示。默认沿用明确的学期顺序，排序可选择课程名、学分；不同成绩制不混排为统一数字排名。

### 成绩详情

使用独立详情页：上方课程名、原始总成绩与官方课程绩点；中间分组展示学分、课程号、学期、性质、类别、考试类型、重修重考；下方为有数据时的成绩组成、替代与认定信息；最下方来源和更新时间。

成绩组成只有接口明确提供才展示，不根据总分反推平时分和期末分。第一版不放排名、成绩趋势、预测绩点和复查按钮。

## 7 考试页

标题栏下先放学期选择，再放“已安排／未安排”分段选项，数量只在成功获取后显示。已安排按日期分组，每张卡片顺序为日期与时间、课程名称、地点、座位。未安排列表显示课程名及原始说明，不显示虚构倒计时。

最近未结束考试优先显示，已结束考试折叠在列表底部“已结束 N 场”。没有可信结构化时间时保留官方时间描述，不擅自判断正在进行或剩余天数。

点击进入考试详情：课程、时间、校区地点、座位、教师、考试说明、来源与更新时间。未提供字段不留大块空白；关键地点缺失显示“尚未公布”。不出现报名、签到、承诺书确认或申请缓考按钮。

空状态写“该学期暂无已安排考试”，并保留“未安排”切换；请求失败显示重试，不复用空状态文案。

## 8 校园卡与网费

两者使用相同详情骨架，但保留各自名称和来源，不合并成总资产。

| 位置 | 校园卡 | 网费 |
| --- | --- | --- |
| 标题栏 | 返回、校园卡 | 返回、网费 |
| 第一张卡 | 主余额、眼睛按钮、更新时间 | 网费余额、眼睛按钮、更新时间 |
| 第二组信息 | 卡状态、余额类型，仅有来源字段时显示 | 账号脱敏、余额单位，仅有来源字段时显示 |
| 底部说明 | 来源、最近成功更新、手动刷新 | 来源、最近成功更新、手动刷新 |

余额在详情也遵循用户的隐藏偏好，不因进入详情自动露出。默认不放消费趋势图、交易流水、网速、流量或在线设备，这些尚不在已确认数据范围。

如果仅能查询单一余额，页面就是一张余额卡加来源说明，不用空白图表填充。无充值、缴费、挂失和付款码按钮。

## 9 消息中心

### 列表布局

标题“消息”，下方先选择来源“全部来源／门户／教务”，再选择“全部／学校未读／学校已读”。服务端不支持某来源的筛选时不要伪造一致能力，显示该来源可用选项。

每行左侧为来源图标或简单色块，中间标题最多两行、摘要一行，底部来源名称；右侧显示时间，学校未读用小点加文字标识。首版只在当前页加载更多，不显示未经验证的跨来源总未读数。

首页消息图标只有在计数范围清楚时显示数字；仅知道某来源有未读时用圆点。加载失败不能把原有未读计数清零。

### 消息详情

独立页面，从上到下为标题、来源与发送时间、原生正文、可选附件列表、底部“查看官方原文”。附件是否可读取取决于实际能力，不预留空列表。

在筛选区域或说明入口标注一次：“阅读仅记录在本机，不改变学校已读状态。”详情底部显示“学校未读／已读”，可另显示“本机已查看”；不用每行同时展示两套状态增加负担。没有“全部标记已读”按钮。

## 10 待办与日程

### 待办与申请

标题栏下放“待办／已办／我的申请”分段选项。列表行展示业务标题、来源系统、业务状态和时间；状态用小标签，整行进入详情。详情只展示已有摘要、状态、时间和来源，不新增流程进度图，除非真实接口提供完整节点。

业务链接放详情底部，标为“在官方系统查看”。第一版没有“提交”“撤销”“批准”“办理”按钮。打开官方页面前明确离开本 App 查询功能。

### 我的日程

作为查询页次级入口，使用日期条加按时间排序的列表。顶部选择日期，右侧“回今天”；每项有时间、标题、地点和来源。仅显示已确认可读取的门户日程，不自动重复并入原生课表。

一天无日程时显示日期和空状态。点击展开只读详情。没有新增、编辑、删除日程入口。校历与作息表作为课表页次级页面，分别呈现学校日期安排和校区节次表，不假定存在官方月历图片。

## 11 我的与设置

从上到下：

1. **身份卡**：默认通用头像、姓名、脱敏学号、学生身份。学院和校区有可靠来源才展示，不开放编辑学校资料。
2. **账号与连接**：门户、教务分别显示“已连接／需登录／暂不可达”，点击查看状态和登录入口；正常连接不是需要反复点击的刷新按钮。
3. **显示分组**：外观、首页设置、课表显示、余额隐藏。
4. **数据与隐私分组**：缓存概览、清除本地数据、后台预览隐私。
5. **关于**：版本、第三方开源说明、功能接入状态。
6. **退出账号**：放页面底部独立一行，说明将清理的本地个人数据后确认。

不展示 SDK 版本、接口地址、Cookie 或调试日志开关给普通用户；后端验证宿主的调试按钮不搬进正式“我的”页。

外观页使用跟随系统、浅色、深色三个选择。首页设置使用带开关的模块列表，排序通过明确的上移／下移或编辑模式完成，不在首页到处放编辑图标。

## 12 首次使用与登录

首次打开只显示一个简洁欢迎页：应用名称、三项能力说明“查课表／看成绩／校园查询”、主要按钮“登录学校账号”，次按钮“了解数据使用”。不做多页强制新手引导。

点击登录进入独立官方认证页面；页面有明显返回和关闭。成功后回到原生首页，分项出现数据。不展示登录成功后长时间全屏转圈；如果只建立门户会话，教务相关区块说明仍需连接，不误称全部登录完成。

用户取消登录可返回未登录的主页面浏览功能目录；个人区域统一显示简洁登录提示，不用四个页面分别弹出登录框。仅允许退出时明确保留的本地数据在未连接时读取，不能因恢复页面暴露已删除账号的数据。

## 13 通用错误与加载位置

| 状态 | 放在哪里 | 具体表现 |
| --- | --- | --- |
| 首次加载 | 对应卡片或列表内容区 | 与最终内容近似的占位，不影响底部导航 |
| 下拉刷新 | 当前页顶部 | 已有内容保留，完成后更新对应时间 |
| 缓存可读但更新失败 | 区块标题下或卡片底部 | “更新失败，显示上次数据”加重试 |
| 离线 | 标题下窄提示条 | “离线，显示缓存”，不逐卡重复整段说明 |
| 会话失效 | 标题下或该功能内容区 | “需要重新登录”按钮，不循环弹窗 |
| 无权限 | 当前内容区 | 说明当前角色不可查看，不显示重新输入密码 |
| 未接入 | 功能入口标签和详情说明 | “暂未接入”，不将按钮偷偷指向业务 WebView |
| 成功为空 | 当前列表内容区 | 与学期／日期相关的空文案 |

错误提示用用户能理解的描述，不把 HTTP 代码和接口路径当正文。严重的缓存数据删除需要确认；正常查询、切周、筛选不需要确认。

## 14 前端实现时的布局验收

- 常规字体下，首页首屏突出完整下一节课，不被新闻或个人介绍占据。
- 从首页一次点击进入成绩、考试、待办或消息；两次以内找到任一核心查询。
- 底部四项入口稳定，详情返回不丢列表位置和筛选。
- 成绩、余额默认隐私行为一致，不把缺失字段显示成 0。
- 周末、跨校区、课程冲突和未安排课程都有可发现入口。
- 大字体时使用列表或单列布局，不把系统字体强制缩小。
- 核心查询界面没有业务 WebView，学校网页只承担认证和主动打开原文。
- 模拟数据只用于开发预览；截图与演示明确标识，正式失败状态不回落到模拟数据。

上述布局可在接口验证后做小范围字段调整，但不改变原生查询定位。没有可靠数据的区块先收起或显示明确状态，不为了视觉完整向后端提出猜测字段。

## 15 后续功能的扩展位置

### 预留规则，不预留空白

首版界面只展示已实现或明确正在接入的功能，不放一排“敬请期待”，也不为未来模块留空卡片。扩展空间通过分类、可配置区块、统一详情页和导航规则实现，不要求首版开发插件平台、远程页面引擎或后台管理系统。

### 底部导航保持四项

今日、课表、查询、我的作为稳定骨架。图书馆、校车、电费、空教室等新功能优先进入查询页，不各自增加底部标签。消息继续从首页右上和查询页进入，不因接入一个新消息源就新增主导航。

只有未来产品范围发生明显变化，且新功能成为独立、高频的主要任务时，才重新评估主导航；不在首版提前放第五项。若未来正式加入办理功能，可评估把“查询”改名为“校园”，但当前仍明确叫“查询”，避免暗示已有办理能力。

### 新功能放置表

以下是位置示例，不是首版承诺或后端开发清单。

| 可能新增的功能 | 一级位置 | 首页可选呈现 | 详情和边界 |
| --- | --- | --- | --- |
| 空教室查询、培养计划 | 查询 → 学习 | 收藏快捷入口 | 筛选结果进入独立原生页 |
| 图书借阅、到期信息 | 查询 → 学习 | 借阅到期摘要卡 | 续借是后续写操作，不能随查询自动开放 |
| 宿舍电费、用水信息 | 查询 → 校园生活 | 独立余额摘要卡 | 不与校园卡余额相加 |
| 校车时刻、校区地图 | 查询 → 出行，新分类按需出现 | 下一班车等可选卡片 | 位置权限仅在具体需要时申请 |
| 校园公告、活动信息 | 查询 → 信息，新分类按需出现 | 用户选择订阅的摘要 | 不自动挤占首页下一节课位置 |
| 个人笔记、学习计划 | 查询 → 工具，新分类按需出现 | 个人安排摘要 | 与学校课程、官方待办注明不同来源 |
| 预约、充值、业务申请 | 未来重新确认范围后确定 | 用户主动固定入口 | 单独设计确认、提交和结果页，首版不实现 |
| 桌面小组件、提醒 | 我的 → 对应显示／提醒设置 | 不需要新增主导航 | 数据依赖现有查询能力；权限按需申请 |

新分类没有可用功能时不显示。分类变多后，查询页增加横向分类筛选条“全部、学习、生活、出行、信息、工具”，功能卡片仍按分组排列；不同时堆两套复杂侧边导航。

### 查询页扩展方式

查询页搜索框下预留逻辑上的“我的常用”区。用户有收藏后才出现，显示最多两行常用入口，其余通过“全部常用”进入；没有收藏时直接展示功能分类，不留下空区。

每个功能入口始终具有一致的信息：名称、图标、简短用途、所属分类、是否原生、当前可用状态。新增功能进入同一搜索范围，支持别名；搜索结果优先精确名称，然后别名，再用途描述。官方网页入口继续明确标注，不和原生功能混淆。

分类内超过六个入口时显示前六个和“查看全部”；完整分类页用清晰列表，避免把查询首页变成长达数十屏的图标墙。用户常用功能可固定，无需依赖运营式推荐排序。

### 首页扩展方式

首页分为固定区和可配置区：

- 固定区：日期与消息入口、必要状态、下一节课、底部导航。
- 快捷区：默认成绩、考试、待办、全部；前三项可在首页设置中替换，“全部”固定指向查询主页。
- 可配置区：今日课程、校园生活、最近考试、待办，以及未来新增的摘要模块。

新摘要模块默认关闭，在“我的 → 首页设置 → 添加模块”中由用户启用并排序，不因版本升级自动插到首页顶部。每个模块只有一个清晰标题、少量关键数据和“查看全部”入口；复杂筛选和完整列表进入独立页面。

例如加入图书借阅后，查询页直接能找到“图书借阅”，首页不会自动多一张卡；用户启用后才展示“近期到期图书”摘要。模块数据加载失败只影响自身，不遮挡课程信息。

### 设置与详情的扩展方式

新增功能特有设置放在该功能页面右上菜单，不全塞进“我的”。跨功能设置才放“我的”：外观、首页模块、数据与隐私，以及未来实际启用后的提醒设置。

新查询页面遵循统一顺序：标题 → 必要筛选 → 关键摘要 → 列表 → 来源和更新时间。简短的单条详情可以用抽屉；内容长、有附件或可能继续进入子页时用独立详情页。不要为每个功能创建不同的返回习惯。

消息来源按实际接入情况动态增加；同一消息在多个来源出现时，只有稳定标识明确对应才合并，不按相似标题猜测去重。多个余额、统计和通知都保留各自来源与时间。

### 给后续前端的设计约束

页面设计时将“功能入口”“首页摘要”“详情页”视为三种独立呈现，同一功能可以只提供入口和详情，不强制制作首页卡。路由使用稳定功能标识，不能靠显示名称定位页面；名称变化不应使收藏失效。

这是 UI 可扩展性约定，不要求当前后端重写共享契约或增加未来接口。后续新增数据能力再扩充相应模块，保留已有页面和查询的行为。首版不要为想象中的未来字段展示空值，也不要默认收集额外个人信息。
