## 2026-09-23 Android 独立查询实测

用户在 `verification` 宿主中的学校官方 WebView 亲自登录。宿主随后对 P01、A01 两域查询探针均显示 `READY`；关闭并重开进程后重新验证仍为 `READY`。登录表单、密码、Cookie、票据及个人响应值未导出。匿名本机请求则分别收到 P01、A01 的 HTTP 302 登录跳转。

本客户端 `SchoolHttp` 对教务查询发 `POST`，`FormBody` 编码为 `application/x-www-form-urlencoded`；门户查询发 `GET`。按下表的实际查询成功说明**这些方法、编码、参数在当前环境下被业务端接受**，不等于学校永久协议承诺。记录仅保留请求名称、字段名、类型、条目数，不保留个人值：

| 查询 | 登录后实际结果 | 证据边界 |
| --- | --- | --- |
| A01/A02 学期 | A01 当前学期、A02 78 项；`code="0"`，`datas.<action>.rows` | POST 表单；A01 `CSDM=SYS, ZCSDM=DQXNXQDM, SFSY=1`，A02 `*order=+DM`。 |
| A04 周次 | 26 项，字段 `serialNumber:number`, `startDate/endDate:string`, `curWeek:boolean` | POST 表单 `XNXQDM`；当前周由返回标记确定。 |
| A05 校区 | 1 项，`id/name:string` | POST 表单 `XNXQDM`。多校区循环已实现，但此账号尚无多校区样本。 |
| A06 节次 | 成功返回数组，项目 `code:number`, `id/name:string`, `sort:number`, `enable:boolean` | POST 表单 `XNXQDM, XQDM`；当前响应没有节次起止时间。 |
| A07 课表 | 学期 24 条已安排课程；当前周 11 条；另观察到非空未排课程 | POST 表单 `XNXQDM, XQDM`，周视图加 `ZC`。`datas.getMyScheduleDetail` 中有 `arrangedList/notArrangeList/practiceList`。课程字段实际含 `courseName`, `teachClassId`, `dayOfWeek`, `beginSection/endSection`, `beginTime/endTime`, `placeName`, `weeksAndTeachers`。未排课程的节次／星期可为 null；实践列表本次为空。教师与周次尚未从组合描述可靠拆分。 |
| G01/G02/G03/G05 | G01 返回 6 个成绩学期；一个历史学期 G02 返回 17 门；G03 从其中一门的 WID 返回 3 个 `itemScores`；G05 返回 `ZPJXFJD:string` | POST 表单。G02 列表实测字段含 `WID,KCH,KCM,XNXQDM,XSZCJ,XF:number,JD,SFJG_DISPLAY,CXCKDM_DISPLAY`；G03 含 `score,gradePoint,pass,itemScores`。本学期 G02 成功为空。G04 尚未接入。 |
| E01 考试 | `arranged=[]`, `notArranged=[]`，`stuInfo/showkeys` 存在 | POST 表单 `XNXQDM`；无非空考试样本，时间地点解析未验证。 |
| P02/P03 余额 | 动态项目 key `card.balance`、`net.balance`，分别对应校园卡／网费；两项本次都成功返回数字 | GET。P03 `d.data.value` 可能是 `number` 或 `string`，`d.data.unit` 为 string。客户端只接受数字文本或明确遮罩；遮罩不转 0。 |
| P10 消息 | 第 1 页返回 1 条；`d.list`, `count`, `noReadCount` | GET，`pagesize` 小写；`log_id:number`, `has_read:boolean`, `content:array`。没有 PUT 已读请求。更多页及其他筛选未实测。 |
| P08/P09 待办 | 待办、已办、我的申请均成功为空，`d.total:number`, `d.list:[]` | GET，`pageSize` 大写；没有非空记录字段样本。 |

Room 缓存从早期 SQLite 结构一次性迁移后仍读出学期课表 24 条及两项余额。进程重启初始会话标为 `UNVERIFIED`，网络探针复验后为 `READY`。断网刷新返回 `NETWORK`，保留 24 条旧课表；恢复网络后重新 `READY`。调试宿主还用无 Cookie 的 A05 白名单查询模拟过期，收到 `AUTH_REQUIRED`，同样保留 24 条，再用原会话刷新恢复。HTTP 200 登录 HTML 的识别由合成单元测试覆盖，尚无真实服务器返回此形态的样本。

## 复现方法

完整构建与单元测试命令见[项目 README](../README.md)。数据验证宿主可运行 `:verification:assembleDebug`，安装包为 verification/build/outputs/apk/debug/verification-debug.apk，启动组件为 edu.neu.campus.verification/.VerificationActivity。宿主不替代正式 App 验收。

### 复现模拟器核验

```powershell
$sdk = "$env:LOCALAPPDATA\Android\Sdk"
& "$sdk\emulator\emulator.exe" -avd TestDevice -gpu swiftshader_indirect -no-boot-anim
& "$sdk\platform-tools\adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk
& "$sdk\platform-tools\adb.exe" shell am start -n edu.neu.campus.neoneu/edu.neu.campus.app.MainActivity
& "$sdk\platform-tools\adb.exe" exec-out screencap -p > shot.png
```

用 `adb shell uiautomator dump /sdcard/ui.xml` 取控件实际坐标，比按截图估算点击位置可靠；查控件文本前先确认前台包名，避免把其他应用的前台界面误当成被测应用。

`verification/` 可用于继续采集**脱敏的字段结构**，不可把姓名、学号、成绩值、余额、密码、Cookie、票据或原始 HAR 提交到仓库。正式 App 的真机验收应单独记录结果，不以此处历史验证宿主记录替代。

截图不入库。冷启动后等待状态稳定再取图，避免截到入场中间帧。Windows 不要对 Gradle 脚本设置 MSYS_NO_PATHCONV=1；需要时只对 adb 设置。
