# 双 AI 分工与交接规范

本项目正式名称为 **NEO NEU**。文中的“后端”仍指 Android 本地数据层，不是远程服务。

## 分工结论

分为前端 AI 和数据接入 AI。用户口中的“后端”在首版对应 **Android 本地数据层与学校接口适配**，不是单独部署的 Web 服务器。两者最终集成到同一个原生 Android App。

前端负责 Compose + Miuix 界面、交互、导航和 ViewModel；数据接入负责学校认证、请求、解析、Room 缓存及 Repository 实现。登录使用必要的官方认证页面，所有核心查询页面仍为原生 UI。

首版只查询，不实现支付、选课、挂失、申请提交或服务端标记已读。无用户新增要求时，不引入自建账号、云端数据库或代管学校密码的服务器。

## 1 双方开始前的共同约定

双方先读 `docs/README.md` 和本文件。产品范围以 01 为准，组件库与技术选型以 02 为准，接口证据以 03 为准，验收以 04 为准。前端必须阅读 [06 UI 页面布局设计](06-UI页面布局设计.md)，页面位置、详情结构和后续扩展规则以 06 为准。

这里的类名、模块名和内部接口是新项目设计，不是学校返回字段。后端 AI 根据实际查询结果建立 `:core:contract` 模块，完成验证后冻结第一版 Kotlin 数据类和接口，前端直接使用。不能两边各写一套同名但字段不同的模型。

执行顺序固定为先后端、再前端，不并行开发：

1. 后端 AI 建立最小 Android 工程、构建配置、共享契约与验证宿主。
2. 后端 AI 完成认证、真实查询、解析、缓存及错误处理，通过验证宿主测试，不等待正式 UI。
3. 后端 AI 交付可构建代码、冻结契约、调用示例、验证记录和限制清单。
4. 前端 AI 在交付工程上实现 Miuix 原生界面，逐页接入真实 Repository，完成最终体验与端到端验收。

验证宿主仅提供登录、查询触发、脱敏状态、退出等最小功能，不做正式产品页面。后端不得以“没有前端”为由停留在 URL 清单或 Python 脚本；必须交付可供 Android 前端调用的 Kotlin 实现。

## 3 前端 AI 的任务

### 交付内容

- 接收后端已验证工程，先运行其构建与测试，再加入 Compose + Miuix 0.9.4 正式界面，验证工具链和 minCompileSdk 要求。
- 今日、课表、查询、我的四个主页面；成绩、考试、余额、消息、待办详情与列表。
- 查询页的加载、失败、空结果、旧缓存、未登录、权限不足、暂未接入状态。
- 学期与周切换、多校区课程展示、未安排课程、大字体、深色模式和返回导航。
- 所有 ViewModel 只依赖契约，不直接拼学校 URL、读 Cookie 或操作 Room。
- 连接真实实现后的集成检查，明确区分“页面完成”和“功能已接入”。

### UI 布局与扩展责任

前端按照 06 文档实现内容层级和位置：今日首屏突出下一节课，消息放右上；课表提供可读的周网格与每日列表；成绩、考试、余额等集中于查询；账号、显示和隐私设置放我的。详情返回要保留来源页面状态。

后续功能扩展属于前端设计责任，第一版就保留以下组织方式：

- 底部固定今日、课表、查询、我的四项；新功能进入查询分类与统一搜索，不逐项增加主导航。
- 功能入口使用稳定标识，名称、图标、分类、用途和可用状态分开定义；收藏和路由不依赖显示名称。
- 首页分固定区、可替换快捷区、可配置摘要区；新增摘要默认关闭，由用户添加、隐藏和排序。
- 同一功能的入口、摘要和详情分别组织，不强制每个功能占据首页卡片。
- 设置区分功能内设置与全局设置；消息、余额等保留来源和各自更新时间。
- 首版不显示未来空卡片或“敬请期待”，不做插件平台、远程页面引擎，不为未来功能要求后端提前实现接口。

图书借阅、电费、校车等仅是 06 中的扩展位置示例，不能视为本次交付需求。实现页面时使用适量的通用布局和功能配置，不用复杂抽象替代具体查询体验。

### 不承担的任务

不自行猜学校 API 字段，不写另一套认证，不为方便展示改变接口语义。金额、绩点和考试时间缺失时不填伪造默认值；不使用 WebView 展示核心业务页面。

演示模式必须有明显“演示数据”标识，使用虚构记录和独立数据源。正式构建不自动从真实接口失败切换成演示数据。

### 完成标准

能运行并演示全部页面状态；真实课表接入后可完成登录返回、切周、详情、离线和失效恢复。release 构建真机滑动与切页无明显卡顿，网络及大块解析不在 UI 线程执行。

前端交接还需说明如何新增一个查询入口、搜索别名和可选首页摘要，以及如何保存用户的首页配置。按照 06 第 14 节检查布局、第 15 节检查扩展方式；验证这些机制不要求接入任何未来功能。

## 4 数据接入 AI 的任务

### 交付内容

- 独立建立 Android 工程、共享契约、依赖装配及最小验证宿主；无需前端先搭架子。
- 从全新会话开始验证官方登录，分别建立门户和教务会话，验证退出、过期与进程重启。
- 逐个核实请求方法、编码、参数、响应包和字段类型；不能把文档中的源码推导直接宣布为实测成功。
- 首先打通学期、周次、校区、节次和个人课表，再接成绩、考试、余额、消息及待办。
- 把学校 DTO 转成统一契约模型；私有 DTO、Cookie 和服务端不透明 ID 不泄露到 UI 逻辑。
- 按账号、来源和学期隔离缓存；保留最近成功版本，错误不覆盖为零或空。
- 提供清晰的 Repository 工厂／依赖注入入口及 Android 认证启动入口，让前端无需了解协议细节。
- 用脱敏结构样本测试解析器、时间单位、空值、错误包、HTML 登录页和字段变化。

### 不承担的任务

不修改 Miuix 主题和业务页面，不构建远端密码代理，不执行学校写操作，不通过猜测 ID 查询他人数据。不因 POST 就拒绝所有查询，也不因 GET 就假定没有副作用。

### 完成标准

每项功能交付“可调用的真实实现 + 查询证据 + 脱敏测试 + 限制说明”。考试没有非空样本时保留明确限制；独立客户端未验证时不能只交 URL 清单宣称完成。

交接清单必须包含：实际构建和测试命令、成功结果、认证启动与生命周期示例、Repository 创建和调用示例、数据库迁移策略、各查询验证状态。若某功能受学校数据或访问条件阻塞，明确列为未完成及具体原因；不得用假实现掩盖，也不得把接口研究任务悄悄交给前端。前端启动前由用户依据清单判断是否接受剩余限制。

## 5 内部契约

### 数据状态

双方需统一以下语义，准确签名写入 `core/contract`：

```kotlin
// 设计示意，非已存在源码。后端须以实测结果实现、编译并冻结契约。
data class QuerySnapshot<T>(
    val data: T?,
    val phase: QueryPhase,
    val lastSuccessEpochMillis: Long?,
    val isStale: Boolean,
    val error: QueryError?
)

enum class QueryPhase { IDLE, LOADING, READY, FAILED }
enum class QueryErrorKind {
    AUTH_REQUIRED, FORBIDDEN, NETWORK, SERVER,
    SCHEMA_CHANGED, UNSUPPORTED, UNKNOWN
}
```

`data == null` 表示从未取得可用数据；成功查询的空列表是非 null 的空集合。`LOADING` 和 `FAILED` 都可以同时保留旧 `data`。`lastSuccessEpochMillis` 是客户端最近成功时间，不冒充学校数据产生时间。需要时另设 `sourceUpdatedAt`。

`QueryError` 只提供类型、可展示的安全说明及是否可重试；不附密码、Cookie、原始个人响应或完整认证 URL。学校 HTML、URL 和网络异常字符串不得未经处理直接展示给用户。

### Repository 列表

| 接口 | 读取维度 | 刷新边界 |
| --- | --- | --- |
| SessionRepository | 当前账号作用域、门户／教务各自状态 | 建立会话、显式退出、失效恢复 |
| AcademicCalendarRepository | 学期、校区、周次、节次 | 按学期与校区 |
| TimetableRepository | 学期、周次、校区或全部校区 | 刷新指定范围，不丢未安排课程 |
| GradeRepository | 学期筛选、课程详情、官方统计 | 详情与列表分开 |
| ExamRepository | 学期，已安排／未安排 | 单学期 |
| BalanceRepository | 校园卡与网费分别建项 | 可单项失败 |
| MessageRepository | 来源、已读筛选、分页 | 新查询重置页，加载更多保留前页 |
| TaskRepository | 待办、已办、我的申请 | 按类型和页码 |
| ServiceRepository | 服务目录与本地收藏 | 目录读取；收藏只写本机 |

建议读取采用 `Flow<QuerySnapshot<T>>`，刷新采用 `suspend` 操作。刷新操作的最终结果统一进入观察流，UI 不再拼另一套回调状态。具体是每个实体观察还是聚合观察，由冻结契约明确。

账号切换由 SessionRepository 发出作用域变化，数据层取消旧账号任务，UI 清除旧 ViewModel 展示，不能等待下一次网络结果才清理。

### 数据字段边界

沿用 04 文档中的内部模型：Term、Campus、Section、CourseRecord、CourseOccurrence、UnscheduledCourse、Grade、GradeSummary、Exam、Balance、Message、SyncState。所有示例模型是应用内部结构，不直接等同学校字段。

金额用十进制字符串或明确最小单位表示，禁止用 Float 保存。原始成绩可为字符串，不能强转数字。学校 ID 使用不透明字符串。学校日期时间按 Asia/Shanghai 解释，网络秒／毫秒转换在适配层完成，UI 统一消费约定单位。

## 6 登录交接

这是两边最容易重复实现的部分，明确分工如下：

1. 前端展示“登录学校账号”入口和认证状态。
2. 数据接入提供 Android 认证启动器，由它管理官方认证页面、可信域与会话；前端只触发，不读取密码。
3. 数据接入验证目标查询域会话可用后更新 SessionRepository，不能只根据网页标题或页面关闭判断成功。
4. 前端观察状态，返回用户原来的原生页面；只恢复读取，不恢复业务写操作。
5. 多个请求同时失效由数据层合并成一次认证需求，前端只展示一个登录流程。

认证宿主可依赖 Android，但不要让 `core/contract` 的数据类携带 WebView 或 Activity。Android 启动器放在认证集成模块，生命周期由宿主按文档调用。

## 7 联调与协作规则

后端 AI 先在项目中完成实现并交付明确的提交或文件状态，前端 AI 从该状态继续。若使用不同分支或 worktree，前端必须从后端交付提交创建分支；不要从空目录另建根工程。

如果只能共用一个目录，严格按所有权写文件，不并发编辑根 Gradle、契约、app Manifest 或同一文档。任何一方都不要 reset、清理或覆盖另一方未提交的改动。

每次交接至少说明：改了什么、公共 API 有无变化、运行命令、已通过的检查、尚未实现的内容。接口变化须提供旧字段到新字段的迁移说明，不能只说“你适配一下”。

一次只集成一个真实查询闭环：

1. 登录 → 学期 → 原生课表 → 退出再登录。
2. 课表离线缓存、切周、多校区、未安排课程。
3. 成绩与官方统计。
4. 考试、余额、消息、待办。

后端先通过验证宿主完成上述数据闭环，再交给前端。前端每完成一个原生页面就连接对应真实实现，不等全部页面画完才联调。每个闭环必须使用真实数据源验收，演示实现不算通过。
