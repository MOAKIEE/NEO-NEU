# 开发指南

更新日期：2026-09-30。本文描述功能范围与当前实现；界面约束见[界面规范](界面规范.md)，已验证与未验证范围见[验证状态](验证状态.md)。

## 产品与范围

NEO NEU 面向东北大学学生，首版只做校园信息查询。使用 Android 原生 Kotlin + Compose + Miuix，不部署自建账号服务器。登录使用原生账号密码页和不可见的官方认证 WebView，需要用户参与时才显示学校验证页；核心查询不能以 WebView 或演示数据替代。

## 功能范围

下表是产品范围，不代表所有能力已实现；当前行为见后文，验收边界见[验证状态](验证状态.md)。

| 功能 | 首版内容 | 明确边界 |
| --- | --- | --- |
| 课表 | 本学期及历史学期、周切换、今日课、课程详情、校区与作息时间 | 不执行学校的课表确认；不改学校排课 |
| 成绩 | 学期筛选、课程、学分、原始成绩、官方绩点、详情 | 不提交成绩复查；不擅自套用绩点公式 |
| 考试 | 已安排与未安排、时间、地点、座位、说明 | 不报名、签到或接受考试承诺书 |
| 校园卡 | 余额、数据时间、官方充值网页入口；卡状态在来源确认后显示 | 应用不提交充值、不挂失、不生成支付码 |
| 网费 | 余额及来源时间、官方充值网页入口 | 应用不提交充值；流量、在线设备等另需网关接口 |
| e 码通 | 学校动态码、首页悬浮球及开关 | 动态码只在内存中展示，不进行通行登记 |
| 学生邮箱与缴费大厅 | 常用工具中的官方网页入口 | 邮件操作及支付由学校网页处理，当前未提供原生只读收件箱 |
| 消息 | 来源、时间、内容、官方已读状态、筛选和分页 | 默认不向学校发送标记已读请求 |
| 待办 | 待办、已办、申请状态列表 | 只读摘要，不执行办理或审批 |
| 服务 | 常用查询入口、搜索、本地收藏 | 收藏先只存在本机，不写门户收藏接口 |
| 设置 | 深浅色、首页卡片顺序、缓存、登录状态 | 不修改学校账号资料或密码 |

教务系统内的消息与门户统一消息是两个来源，分别标识，不把一方计数当作全校消息总数。校园资讯作为低优先级可选卡片，不影响主要查询任务。

## 状态与隐私

| 情况 | 显示与动作 |
| --- | --- |
| 首次未登录 | 学校官方登录入口与功能说明，不展示仿真个人数据 |
| 离线且有缓存 | 展示最后成功数据和时间，允许本地浏览 |
| 登录失效 | 保留页面位置，一次登录提示，成功后恢复读取 |
| 单项失败 | 卡片级错误与重试，不把失败渲染为 0 元或无课程 |
| 空结果 | 标明学期、时间范围与来源，必要时提供官方查询入口 |
| 数据格式变化 | 保留旧缓存，提示更新失败，记录脱敏诊断信息 |

余额提供本地隐藏开关；应用切换预览的隐私保护仍是待实现目标。课程名称、成绩等不写入崩溃日志。退出时删除保存的账号密码、清理会话和关联个人缓存；如保留离线数据，必须由用户明确选择。

## 业务展示约束

- 四个底部入口固定为今日、课表、查询、我的；成绩与考试可从查询和首页快捷入口进入，消息从今日右上角进入。
- 日期使用 Asia/Shanghai，教学周取学校校历；各卡独立刷新，余额失败不能阻塞课表。历史数据与详情按需加载。
- 课程实例保留日期和来源标识。同名连续节次仅在教师、地点、日期、来源和时间衔接一致时才可合并展示，底层保留分节；未排课程不能丢弃，多校区要汇总并提示真实冲突。
- 成绩展示学校原始成绩与官方绩点；总平均绩点不能标成当前筛选学期的绩点。考试必须区分未安排、缺字段与查询失败；承诺书等业务要求交给用户在官方页面处理。
- 当前只接入门户消息并标注来源；将来接入教务消息时须分别标注，不合并为全校消息计数。本机阅读与学校已读分开，打开官方原文可能产生学校端访问或已读记录。消息富文本转为受控原生内容。

## 页面实际行为

- 今日只以学校标记的当前学期/教学周展示课程，不再用第一学期/第一周冒充当前值。周次取得后独立加载对应周课表；学校时区时钟按分钟更新，跨日重新读取学期、周次和对应课表。缓存中的当前周标记必须仍覆盖当天日期；缺少周日期时只接受当天同步确认的标记。跨周尚未确认或离线时不把上一周课程当作今日课程，同一教学周内的离线缓存仍可浏览。尚未取得数据、成功无课、失败、旧缓存分别呈现。
- 课程状态只使用可解析且完整的起止时间，下课边界不继续显示“正在上课”。存在不完整时间或旧缓存时显示待确认，不推断已全部结束或冲突。
- 课表以返回节次及课程实际覆盖范围生成坐标轴，不限制为固定 12 节；连续课程显示为跨节块，相邻单节课程不算冲突。日期高亮比较实际日期。大字体或全部校区含多个校区时降级为列表；列表带校区名称并按校区排序。
- 校历仅展示学校返回的教学周及日期。作息按返回校区列出节次；缺少时间时明确说明，不补造通用作息、选退课窗口、考试周或假期。
- 成绩保留原始成绩与官方 GPA；缺失字段不默认初修/正常通过。统计与详情失败提供重试及旧缓存说明。
- 考试详情路由携带所选学期和选中记录，避免按课程名在当前学期误匹配。刷新失败时保留旧安排并显示最近成功同步时间、失败原因及重试或登录入口；无缓存时区分加载、失败与记录不可用。当前契约没有稳定考试 ID，记录已变化/不可用时要求返回列表重新选择；不提供深链接持久身份保证。
- 消息首次进入自动获取；按学校已读状态发起查询，30 条一页，提供上一页/下一页。详情使用同一页码/状态快照。本机阅读只在取得正文记录后标记；未提供学校状态时不默认未读。当前只接入门户来源，不展示虚构的教务独立来源。
- 待办切分类会发起查询；非空记录仍受现有适配器的 SCHEMA_CHANGED 限制。
- 余额展示数值、遮罩及同步信息，不展示无来源的卡状态、在线状态或套餐；充值按钮在余额失败时仍可打开学校官方网页。打开网页不代表充值成功，返回后仍以学校余额查询为准。
- 查询页保持学习查询双卡片、常用工具宫格和学校服务目录入口的原有布局及工具顺序；e 码通、充值、邮箱等仍在同一宫格中。搜索结果与宫格统一图标，长标题与标签可换行。服务目录按学校平台与充值缴费分组。学校服务网页在应用内 WebView 打开，使用紧凑标题栏、当前域名、加载进度、刷新与关闭操作；返回优先回退网页历史，加载失败显示原生重试卡片。网页使用宽视口、概览缩放和双指缩放，正文占满标题栏下方剩余空间；首屏提交显示前提供加载提示，持续加载且 30 秒仍未提交可见页面时提示超时。刷新与重试从该服务的固定官方入口重新打开；WebView 在 AndroidView 释放时清理销毁。共享本应用的学校网页 Cookie；官方 App 的私有 Cookie 不跨应用共享。其他服务先打开个人门户并选择其当前目录中的已核验手机入口；校园卡和网费先经过门户的缴费大厅认证，邮箱优先使用学校发布的邮箱 CAS 入口。若实际进入学校 CAS，使用保存的统一认证凭据静默尝试一次；需要人工验证时先清理旧会话，再从固定官方入口重新登录。独立邮箱表单不代填学号或统一认证密码。消息与待办的门户按钮也走内置网页。路径、失败回退及证据见[官方页面会话](官方页面会话.md)。
- e 码通原样编码学校返回的动态码，依据同级有效时间提前清除和刷新；页面开关控制首页悬浮入口，采用 Miuix 圆角短胶囊与扫描图标，支持拖动、松手吸附左右边缘、闲置 3 秒半隐藏，并在本机记住停靠侧与相对高度；点击后在首页弹窗显示二维码。动态码不进入 Room、日志、剪贴板或可恢复状态，离开页面与退后台后清除；展示期间禁用系统截屏和最近任务预览。
- 双域刚连接时，应用用只读 `/user-info` 检查 e 码通会话并尝试一次学校主页 SSO；打开码页时仍未连接则再次尝试，以取码接口成功作为最终判定。学校 CAS 若要求账号密码，用户需在可见官方页面自行认证。适配层的预连接不读取或保存动态码。
- 我的采用账号概览、偏好设置、数据与隐私及关于分组；主题选项和关于说明按需展开，退出入口合并为一个。标题栏使用 CampusTopBar，由 MainScreen 应用并消费 Scaffold 内边距，避免各页重复系统边距。账号显示通用“学校账号”，不推断身份、学历。当前没有独立“只清缓存”API，操作明确命名为“退出并清除本地数据”，说明会话和当前账号缓存都会清除；Miuix OverlayDialog 承担确认。

## 页面状态与适配

登录时序补充：所有登录请求先尝试静默恢复当前会话及本机可用凭据，已有尝试直接复用；成功留在当前页面，失败才进入原生页，回退页不会重复自动提交。服务页也先重试自己的静默连接流程。后台恢复需要人工交互时只提示并暂存网页接续；进入原生页后点击「继续学校验证」显示原网页。尚未尝试过的独立原生入口自动读取可用凭据并尝试一次；暂停凭据只自动填入。旋转和状态刷新不重复触发，异步读取不覆盖用户编辑。详见[登录流程](登录流程.md)。

`SaveableStateHolder` 按主标签/详情路由隔离保存状态，筛选、查询词、学期 ID、周次、校区及列表模式使用可保存状态；滚动组件参与 Compose 保存机制。账号作用域变化时重建页面保存容器，避免旧作用域状态沿用。启动时复验已有会话；回到前台复验已有会话，60 秒内合并重复检查；明确失效后，应用在后台打开所需学校入口，先复用共享 Cookie，必要时尝试本机凭据。暂不可达保留网络错误，不自动重复提交密码；用户主动点击登录时可重试或进入原生凭据页。静默尝试不轮换账号作用域，可见的重新认证仍按原逻辑隔离缓存。学校登录入口先执行静默恢复，失败后才显示 Miuix 原生学号、密码页，凭据仅在本机加密保存；不可见的学校 WebView 先复用会话，必要时自动填表并点击学校登录按钮，每轮最多一次。验证码、二次认证或未知交互出现时，进入可见页前销毁旧网页、清理 Cookie 和网页存储并轮换作用域，重新打开固定学校入口供用户完成登录，完成后自动复验，也可点击「完成验证，检查连接」。密码错误暂停自动提交，离开应用取消不可见尝试。实现与生命周期见[登录流程](登录流程.md)。未在登录页完成检查就返回时，主界面复验连接；登录页已确认双域可用时不重复发起探针。已连接的教务/门户触发对应数据恢复。

主框架对标签与二级路由分别提供转场动画；二级页面统一用 `CampusPageEnter` 做挂载入场，列表首屏用 `StaggeredAppear` 逐项出现。骨架屏仅在真实加载态出现，空结果与失败不渲染为占位形状。

首页快捷区和余额区、查询重点入口与工具面板根据窄屏/字体放大调整列数；课表大字体切列表。详情补充系统底部安全区及键盘避让。此处记录实现机制，尚不是旋转、进程恢复、所有大字体及真机手势验收通过。

新增入口沿用 FeatureRegistry 和稳定路由；新增首页模块默认关闭，保留用户配置。独立欢迎页、外观缩略预览、后台预览隐私设置与完整宽屏排版尚未完成。

## 前端装配

```kotlin
val campus = CampusData.get(applicationContext) // 应用进程中保持单实例
startActivity(OfficialLogin.intent(this))       // 原生填写凭据，后台认证；必要时继续学校验证

lifecycleScope.launch {
    campus.session.verify()                       // 进程重启后复验门户和教务
    campus.academic.refreshTerms()
    val term = campus.academic.terms().value.data?.firstOrNull { it.isCurrent } ?: return@launch
    campus.academic.refreshWeeks(term.id)
    campus.academic.refreshCampuses(term.id)
    campus.academic.refreshTimetable(term.id, null) // 学期视图，遍历所有返回校区
    val table = campus.academic.timetable(term.id, null).value
    campus.portal.refreshBalance(BalanceKind.CAMPUS_CARD)
    val card = campus.portal.balance(BalanceKind.CAMPUS_CARD).value
    campus.portal.refreshMessages(page = 1, pageSize = 30)
    val messages = campus.portal.messages(page = 1, pageSize = 30).value
    // 观察 Flow<QuerySnapshot<T>>；FAILED 时可能保留旧 data
}
```

认证入口由 `integration/auth-web` 提供；业务查询使用 `CampusData.academic`、`.portal`、`.session` 的 `core/contract` 接口。正式业务页面不得直接用 `CampusData.localSession`、`SchoolHttp`、Cookie 或学校 URL。验证宿主不进入正式发行包。App Manifest 应保留 `INTERNET`、禁用明文传输及备份；使用 Miuix 0.9.4 时须保留 compileSdk 37、minSdk 24，并完成正式 UI 的 targetSdk 适配。

`NEO NEU` 是面向用户和 Gradle 根工程的名称；现有 `edu.neu.campus.*` 是 Kotlin 命名空间及 debug 宿主 ID，不应为改名批量替换。正式 `app` 当前的 `applicationId` 是 `edu.neu.campus.neoneu`，发布前仍需核对。

`QuerySnapshot.data == null` 表示尚无成功数据；成功空列表是非 null 空集合。刷新失败可保留旧 `data`、原 `lastSuccessEpochMillis` 和 `isStale=true`。Room 只在完整解析成功后写入；账号作用域为本机随机 ID，退出清除当前范围与 WebView Cookie。仅打开原生凭据页不会轮换作用域；提交新的凭据时清理旧 Cookie 并轮换作用域。静默恢复保留作用域及旧缓存；进入可见学校表单前清理 Cookie 和网页存储、轮换作用域并重新打开固定入口，避免换号后继承另一账号的业务会话。保存凭据绑定随机作用域，恢复后只用门户返回的账号字段与输入账号精确比较；缺失时暂停自动提交，不匹配时删除凭据。更换学校账号可先在「我的」退出并清除本地数据，保存新凭据也会清理旧会话。当前尚未验证跨域共享身份，不用门户字段进行缓存迁移。进程重启先标 `UNVERIFIED`，由 `session.verify()` 更新两域状态。

## 契约冻结说明

冻结范围是当前 `core/contract` 的 `SessionRepository`、`AcademicRepository`、`PortalRepository`、模型、错误与状态语义。`Grade.sourceId` 仅是调用详情的本地不透明句柄；UI 不解析其内容。若前端提出必要字段变更，须修改契约、实现和测试并记录迁移。未取得非空考试／待办、跨校区或实践样本时，UI 应显示“当前账户数据样本未验证”或对应错误状态，不以演示数据和业务 WebView 代替。

### 缓存迁移

Room schema v1 位于 data/database/schemas/。旧 SQLite 已有一次迁移；后续版本必须提供显式 migration，不允许 destructive fallback。当前查询边界见[接口参考](接口参考.md)；实际白名单以 `SchoolCall` 为准。
