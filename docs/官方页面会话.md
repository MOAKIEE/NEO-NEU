# 官方页面会话

更新日期：2026-09-30。目标是优先沿用个人门户的应用入口和本应用的学校会话，减少重复登录。实际免登录效果仍需真实账号验收。

## 个人门户调查

匿名只读访问[门户应用目录](https://personal.neu.edu.cn/portal/appmarket/frontend/default/getApp?limit=999&type=all&cate_id=)返回 `e=0`、`d.list` 和 `d.cates`。2026-09-30 公开目录中，教务系统（新）的地址为 `https://jwxt.neu.edu.cn`，缴费服务大厅的地址为 `https://pay.neu.edu.cn/drCasLogin`。这只是公开目录，不能代表所有账号登录后可见的服务。

本机留存的门户前端 `terminalOpen` 根据设备选择 `extra_url.mobile_url`，为空时使用 `url`，随后以新窗口打开该地址。未在此函数中看到额外的票据兑换；它另有访问统计写调用，应用自己的适配器不调用该写接口。新窗口仍使用同一浏览器 Cookie，因此“从门户打开免登录”依赖门户配置的目标入口及已有 CAS／业务会话，不能仅凭门户已连接判定所有服务已登录。留存脚本属于历史证据，不声称已核对当前登录后全部脚本。

正式实现先在不可见 WebView 打开[个人门户](https://personal.neu.edu.cn/portal)，只读核对门户连接与保存账号，再使用同一 CookieManager 读取当前目录，按门户的手机入口规则选择已核验的服务。目录名称须唯一匹配；地址只接受服务的固定 HTTPS origin 和已核验路径，不接受外部 origin、非默认端口、用户信息、票据查询参数或未知认证路径。目录缺失、重复或结构变化时使用固定官方入口，不持久化原始目录。

## 各服务的路径

| 服务 | 优先打开方式 | 后续行为 |
| --- | --- | --- |
| 个人门户 | 学校门户入口 | 只读探针确认后显示原网页 |
| 本科教务 | 门户目录中的教务系统（新）手机入口 | 学校自己的 CAS 重定向；目录不可用时使用现有教务主页 |
| 缴费服务大厅 | 门户目录中的 `drCasLogin` | 匿名请求实际返回 302 至学校 CAS |
| 校园卡／网费充值 | 先走门户的缴费大厅入口 | 完成学校跳转后再打开所选固定充值页；直接匿名访问充值页会进入 `/tologin.html` |
| 学生邮箱 | 门户有唯一且已核验的邮箱入口时沿用；否则使用官方邮箱 CAS 入口 | 不把学校账号密码填入独立邮箱登录表单 |
| e 码通 | 门户有已核验入口时沿用；否则使用官方前端主页 | 前端先读取 `/user-info`，设置 `KC_REDIRECT` 后进入自己的 SSO；不绕过该前端直接伪造回调 |

[学生邮箱首页](https://mails.neu.edu.cn/)当前同时提供邮箱登录和统一身份认证，其公开配置 `CasLoginUrl` 为 `/coremail/cmcu_addon/dbdxsso.jsp`；匿名访问[该入口](https://mails.neu.edu.cn/coremail/cmcu_addon/dbdxsso.jsp)实际 302 至 `pass.neu.edu.cn/tpass/login`。独立邮箱页面使用 `uid`、`domain` 和 `fakePassword` 等字段，不能据此推断邮箱账号等于学号、邮箱密码等于统一认证密码，也不自动拼接邮箱地址。学校若仍返回独立邮箱表单，原网页显示提示，用户按邮箱页面要求填写自己的邮箱账号和密码；本轮未新增邮箱凭据保存或代填。

e 码通前端行为来源为[学校公开脚本](https://ecode.neu.edu.cn/ecode/js/app.fa3a054d.js)。充值与缴费大厅入口还可从[学校服务页](https://www.neu.edu.cn/sfrd/jzg.htm)核对。

## 静默恢复与交接

只有实际到达精确的学校 CAS origin／登录路径时才读取保存的学校凭据，继续使用既有 DOM 校验与学校提交按钮。一次服务打开只允许一次自动提交，网页后续再跳到 CAS 时沿用同一预算与回调，不重置提交标记。密码未通过、凭据暂停或账号无法核对时不继续自动提交。验证码、二次认证和未知交互将同一个 WebView 交给可见学校验证页。

交接只传内存 token 与固定服务枚举；Intent、Compose 可恢复状态和日志不携带密码、Cookie、票据或完整导航 URL。可见学校验证仍按[登录流程](登录流程.md)轮换账号作用域并设置安全窗口，验证码与已填字段不因交接重载。服务验证页保留当前服务标题，完成后返回原服务，不自动绕行教务认证。刷新从固定认证入口重新开始，不重放最近的 POST。

服务连接与原生登录共用串行锁。不可见尝试仅在页面位于前台时执行，后台或退出页面取消并释放浏览器；已展示的页面由 AndroidView 释放时销毁。晚到的 CAS 重定向先隐藏，再尝试剩余静默预算，必要时转为可见学校验证。失败页可以重新连接、登录学校账号，或直接尝试固定学校服务入口。

消息、待办中的“打开官方门户”也使用本应用的网页容器，复用相同 Cookie；复制的门户地址仍是无凭据的公开入口。学校网页可以自行产生访问记录，应用不执行充值、支付、邮件操作或门户收藏写入。

网页到达目标域只表示可展示，不能证明权限、邮箱登录、充值或支付成功。e 码通仍以实际取码结果为准，余额仍以 Repository 查询为准。验证边界见[验证状态](验证状态.md)。
