## 1 证据与限制

本文采用四种证据：

- **页面验证**：在已登录 Edge 中正常打开功能，确认实际显示及字段。
- **资源观察**：浏览器资源清单中出现请求 URL。不能仅据此确认状态码、请求方法或响应正文。
- **源码确认**：读取页面实际引用的公开 JavaScript，确认调用方法、参数和消费字段。服务器当前是否始终返回这些字段仍需响应样本。
- **独立客户端回放**：2026-09-23 新增，范围与结果见上节；未列出的接口仍待回放。

早期浏览器研究没有导出 Cookie 或票据；一次直接打开日历 JSON URL 返回 `ERR_BLOCKED_BY_CLIENT`。随后已在独立 Android 宿主完成上节列出的登录后查询，未导出原始个人响应。下文表格中的“源码”标注是原研究状态，需结合上节实测读取。

## 3 统一认证

公开登录表单包括 `un`、`pd`、`rsa`、`ul`、`pl`、`lt`、`execution`、`_eventId` 等字段。2026-03-02 版本的 `login_neu.js` 使用 `RSAEncryptor` 加密用户名与密码拼接值，填入 `rsa` 后提交；页面同时存在历史脚本引用。因此不能照搬网上旧版 DES 登录脚本，也不能根据字段名猜完整协议。

未登录请求观察到 Cookie 名称 `JSESSIONID`、`Language`，门户链路还出现 `SESS_ID`，教务链路出现 `route`。这只是名称观察，未验证各自认证职责、作用域或有效期。APK 中 `CASTGC`、`neuCasLogin`、Cookie 同步符号提供补充线索，不能当作完整认证实现。

首版建议使用官方登录页面，由用户在自己的手机内完成认证。会话协调器至少区分未登录、正在认证、门户可用、教务待建立、全部可用、失效和网络不可达。WebView 与原生请求之间的会话衔接应在实现阶段单独验证；外部浏览器没有天然可供新 App 读取的 Cookie。

不把密码写入本地数据库、日志或自建服务器。首次版本不自动提交保存的密码，不实现短信发送或验证码绕过。官方认证与应用页面之间不注入读取表单的桥接。

### 余额读取

首页已显示校园卡余额卡片和网费余额。公开脚本的流程是 P02 获取当前用户的数据项目，再逐项用 P03 获取详情。`id` 是动态的不透明值，禁止把本次账号的值写死，也不要从其他用户猜 ID。

来源优先采用门户这条 HTTPS 查询链路。具体哪一项对应校园卡或网费，应从返回的稳定 key 与名称一起确认，记录字段类型、币种／单位、更新时间。失败不能填 0，界面隐藏余额也不能被误判成服务器没有返回余额。

2026-09-22 研究时仅确认页面与调用链；2026-09-23 独立客户端已验证 P02/P03 的动态 key 和数字余额，见顶部实测表。遮罩值仍只有合成测试样本。旧一卡通的主钱包、补助等不同余额不要擅自相加。

### 门户日程

P06 中 `class`、`other` 的项目使用 `is_show` 决定默认筛选，不能固定为本次观察到的 1—6 分类。P07 的 `start/end` 按代码乘以 1000 和实际 URL 确认是毫秒时间戳；不能和消息的时间筛选混用。

当前门户日程确实显示课程及地点，但界面标签为个人日历，不能据此认定其覆盖所有新教务排课。首版以教务个人课表为课程主源，门户日程作为另一个来源，避免同一课程展示两次。

### 消息

源码确认筛选值：全部 `0`、已读 `1`、未读 `2`。注意参数大小写是 `pagesize`，而待办使用 `pageSize`。源码可见 `title`、`content`、`time`、`has_read`、`url`、`log_id` 等字段消费；最终类型待样本。

点击原网页消息可调用 `ucs/msgRead` 映射，使用 PUT，参数为 `ucs_id=log_id`；全部已读使用 `whole=1`。查询版不复制这一副作用，不调用这些写操作。未读消息的正文读取、可跳转原文和更新已读要拆开设计。

## 5 新教务的请求封装

基址记作 **J = `https://jwxt.neu.edu.cn/jwapp`**。

主页是独立前端，子应用由 iframe 承载：课表 `kbapp`、成绩 `cjzhcxapp`、考试 `wdkwapp`。不能用主页 API 的字段格式直接解析所有子应用。

公共 `jwPackagingMethod.min.js` 的 `$.jwAjax` 默认使用 **POST**。因此“首版只做查询”不能实现成“只允许 GET”；应对允许的查询端点建立明确白名单。

该封装处理 `/sys/` 前缀时拼接 `context_path`；相对 `/api/`、`/modules/` 交给 `WIS_EMAP_SERV.getAbsPath`。下表完整路径由当前子应用与源码解析得到，尚需实际网络样本确认是否存在部署差异或追加参数。

源码中标准响应大致为 `code == "0"` 后读取 `datas[动作名]`，若带 `extParams` 还检查业务状态；异常格式会交由调用方处理。不要把回调消费的对象直接当成原始响应根。403、401 与业务失败应分开解释。

默认封装未在相关调用处显式设 JSON Content-Type，按 jQuery 默认是表单编码的候选方案；是否有全局拦截器修改编码、请求头或参数，仍须请求样本确认。

## 8 考试接口与字段

**E01：POST 候选** `J/sys/wdkwapp/api/wdks/queryMyExamArrangeMent.do`。

方法依据 `jwAjax` 默认行为，参数 `XNXQDM` 来自当前学期。源码回调消费：

- `stuInfo`：页面学生信息及承诺书状态。
- `arranged`：已安排考试。
- `notArranged`：未安排考试。
- `showkeys`：当前允许展示的详情字段。

考试项消费 `KCM`（课程）、`KCH`（课程号）、`KXH`、`KSZT`（0 未开始、1 进行中、2 已完成）、`KSSJMS`（时间描述）、`JASMC`（地点）、`ZWH`（座位）、`SKJS`（教师）、`XSS`（人数），以及 `KSSM`（说明）。这些是源代码字段证据；本次页面为空，尚未获得非空真实响应核对类型和时间格式。

`KSSJMS` 是展示描述，不能未经解析规则验证就用于精确提醒。未公布地点和接口失败分开处理。

`readCommitmentLetter.do`、`signin.do`、`signout.do` 不属于查询白名单；补考报名、缓考申请也不进入首版。页面逻辑含承诺书要求，应由用户在官方界面处理，不自动代为接受。

## 9 明确禁止被同步器调用的操作

这是首版功能边界，不是对 HTTP 方法的泛化判断。

| 操作 | 已发现的路径或行为 | 首版处理 |
| --- | --- | --- |
| 门户收藏写入 | `/appmarket/frontend/default/collect`，PUT | 改为本机收藏 |
| 标记消息已读 | `ucs/msgRead`，PUT | 默认只保存本地阅读状态 |
| 资讯已读／收藏 | `read-article`、`collect`、`readall` | 不随查询批量调用 |
| 课表确认 | `/api/wdkbcx/confirmSchedule.do` | 不提供按钮、不调用 |
| 成绩复查写入 | `save.do`、`rollback.do` | 不调用 |
| 考试确认／报名 | 承诺书、signin、signout、申请接口 | 不调用 |
| 支付与挂失 | pay 订单、旧一卡通挂失 | 不创建订单或办理 |

官方网页自身可能产生访问日志或最近使用记录；“只读研究”指未主动执行业务变更，不声称学校网页零副作用。

## 10 接入前仍需验证

1. 在手机 WebView 内从未登录开始完成官方认证，并分别建立门户与教务会话。
2. 获取允许查询接口的实际方法、Content-Type、必要请求头、编码及脱敏响应样本；当前公开源码推导不能替代这一步。
3. 核实 `WIS_EMAP_SERV.getAbsPath` 后的部署路径、上下文和是否有额外请求拦截器。
4. 验证 401、403、HTML 登录页、业务错误、账号退出和会话超时。
5. 确认非空考试、历史学期、跨校区、实验课、未安排课程与余额动态 ID 的映射。
6. 校外网络与 WebVPN 用独立测试记录；不重用当前浏览器里的票据或硬编码其编码 URL。

如果使用 HAR 辅助核验，应在本机脱敏后只保留查询请求：去除 Cookie、Authorization、Set-Cookie、票据、密码、姓名学号及个人值。不要上传原始 HAR 到公共仓库。可以先在查询适配器中记录脱敏结构，用最少一次请求完成必要核对。
