# 实施与验证计划

## 首版实施原则

先实现一条真实查询链路，再扩展页面。2026-09-23 已建立 Android 数据工程和可安装的 debug 验证宿主，真实接入进度与限制见 `docs/handoff/data.md`。研究 URL 不单独计为已完成功能。

交付必须是原生查询 App：核心页面用 Compose + Miuix，认证完成后退出认证网页。禁止将学校业务网页嵌入核心页面或用网页替代未实现的接口。浏览器查看原文只能作为用户主动选择的补充入口。

面向学生自用，默认只在手机本地保存数据，无自建账号与云端。首版通过手动刷新和打开页面时受控更新满足查询需求；后台提醒和高频轮询暂不成为交付前提。

## 阶段与完成条件

| 阶段 | 内容 | 必须交付的证据 |
| --- | --- | --- |
| 1 后端工程 | Kotlin Android 工程、共享契约、debug 验证宿主；工具链考虑 Miuix 要求 | 后端模块可编译，验证宿主可安装 |
| 2 登录试验 | 官方页面认证、门户和教务分域会话 | 从全新安装到首次查询、进程重启与退出记录 |
| 3 课表闭环 | 学期、周次、校区、节次、课表、缓存 | 与官方周课表逐项一致，实验与未安排课程保留 |
| 4 成绩和考试 | 列表、详情、官方统计、考试空状态 | 学期筛选与官方结果一致；非空考试样本待补 |
| 5 余额和消息 | 数据项发现、详情、消息分页、待办 | 不写死个人 ID；失败不归零；没有已读写请求 |
| 6 后端交接 | 验证宿主完成离线、超时、失效与进程恢复，冻结契约 | 构建命令、调用示例、查询验证状态与限制清单 |
| 7 前端实现 | 接收后端工程，Compose + Miuix 原生页面逐页接入 | 真实数据页面、主题、导航、抽屉及全部错误状态 |
| 8 最终适配 | 大字体、深色、切后台、真机流畅度和端到端复验 | 测试矩阵及缺陷关闭清单 |

按单人熟悉 Android 开发估计，构建和认证试验约 2—4 个工作日，课表闭环约 3—5 日，其他查询约 5—8 日，适配约 3—5 日。总计约 3—5 周作为规划参考，取决于登录与接口实际契约，不作为完成承诺。

## 内部数据模型

| 模型 | 必要内容 |
| --- | --- |
| AccountScope | 本机账号作用域、当前角色；不存明文密码 |
| Term | 来源代码、显示名称、教学周日期范围 |
| Campus | 来源代码、名称 |
| Section | 学期、校区、节次、开始结束时间 |
| CourseRecord | 来源稳定 ID、课程元信息、原始排课规则 |
| CourseOccurrence | 具体日期、周次、节次、教师、地点、来源记录 |
| UnscheduledCourse | 未安排原因、课程元信息 |
| Grade | 原始成绩、学分、官方绩点、重修性质、来源 ID |
| GradeSummary | 官方统计值、统计范围、时间 |
| Exam | 原始时间说明、经确认的结构化时间、地点、座位、状态 |
| Balance | 项目 key、金额原始值、数值与单位、来源时间 |
| Message | 来源、消息 ID、官方已读、本地已读、时间、内容 |
| SyncState | 最近尝试、最近成功、来源版本、错误类型、过期标识 |

数据库以账号、来源、学期分区。服务器 DTO 与本地模型独立，字段新增不要求立即重写 UI。原始 HTML 不直接作为 Compose 富文本执行，链接交给受控导航。

## 同步策略

先显示缓存再更新；完整成功才事务性替换该范围数据。网络失败、字段解析失败、认证跳转都保留旧数据。空结果只有在认证、响应格式、查询范围均确认成功时才可覆盖旧结果。

同一查询合并并发；首次自动同步限制并发数量。重试采用退避，对 401 进入认证协调，对 403 提示权限，不反复请求。避免每次切底部导航都重拉整个学期或全量成绩。

缓存过期时间作为本地策略配置：课表进入前台时检查，成绩和余额按需刷新，消息按页查询。界面始终显示最近成功时间，不制造“实时余额”承诺。

## 查询白名单

网络层维护明确的逻辑操作，如 `ReadTimetable`、`ReadGrades`、`ReadExams`、`ReadBalances`、`ReadMessages`。每项映射固定的主机、路径、方法和参数模板。不能提供任意 URL 加 Cookie 的通用调试入口。

POST 查询按已验证语义允许；课表确认、已读写入、充值、挂失等即使位于同域也不允许被自动同步调用。官方浏览器入口和原生查询客户端分开，不自动重放网页写请求。

## 最小测试集合

| 测试 | 通过标准 |
| --- | --- |
| 全新安装登录 | 能进入官方认证，成功建立所需分域会话 |
| 进程被杀 | 再打开会话状态正确，不显示另一账号旧数据 |
| 认证过期 | 多接口同时失效只提示一次，不无限刷新 |
| HTML 冒充成功 | HTTP 200 登录 HTML 被识别为失效，不解析为空列表 |
| 课表周次 | 单双周、临时变化和学期边界准确 |
| 多校区 | 不因默认只取第一个校区漏课 |
| 多种课程 | 实验、实践、未安排节次和冲突可见 |
| 历史成绩 | 与官方指定学期核对课程数、总成绩、重修标识 |
| 官方绩点 | 展示 G05 原值并标清统计范围，不误当筛选学期值 |
| 无考试 | 成功为空与请求失败不同；非空样本到位后追加验证 |
| 余额失败 | 不显示 0，不把遮罩字符串当金额 |
| 消息阅读 | 查询日志没有 PUT 已读或全部已读请求 |
| 离线 | 已缓存课表和成绩可读，余额明确标旧数据 |
| 本地清理 | 清除当前账号缓存和会话，数据库与通知不串号 |
| 大字体 | 主导航、课程详情与成绩值不裁切 |
| 原生页面 | 核心查询流程无需加载业务 WebView；接口未完成如实标注 |
| 流畅度 | 真机 release 构建检查长列表、课表切周与刷新，主线程不执行网络和大块解析，切页不重建整份数据 |
| 老系统 | API 24 基础安装验证；API 29+ 主流设备重点测试 |

接口解析单元测试使用手工构造或严格脱敏的结构样本，覆盖未知字段、空值、错误包和 HTML。不能把真实账号成绩与 Cookie 固化为测试夹具。

## 下一步所需信息

目前产品方向已经够明确，不需要再让用户选一遍功能。剩余问题主要是工程验证：

1. Android 手机上的首次认证和会话保留是否成功。需要真机时再请用户操作官方登录。
2. 主要查询接口的实际网络契约和脱敏 JSON，尤其课表课程嵌套对象、成绩表格响应和余额 key。
3. 当前账号无已安排考试，未来有考试时补一次非空样本即可，不需要寻找他人账号。
4. 是否开启提醒和桌面小组件可在查询版可用后决定，不阻塞首版。

先完成构建和课表查询原型，再以结果决定是否扩大接入范围。当前所有已知缺口已在接口文档中按模块保留，后续应更新同一份文档，避免另起不一致版本。
